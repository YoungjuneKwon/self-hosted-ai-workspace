# self-hosted-ai-workspace

AI 코딩 에이전트로 매일 일하기 위한 컨테이너를 스크립트 하나로 세웁니다.

English: [../../README.md](../../README.md)

---

클라우드 작업환경은 바로 열리고 매번 깨끗합니다. 가끔 쓰는 용도라면 그쪽이 맞는 거래입니다.
매일 쓰는 용도라면 세션마다 같은 도구와 파일과 권한을 다시 세우게 되고, 자격 증명과 맥락과
한계를 남이 관리하는 것을 받아들여야 합니다.

호텔이냐 집이냐의 문제입니다. 대부분은 호텔이 맞습니다. 이 저장소는 그것이 더는 맞지 않게
되는 경우를 위한 것입니다.

## 차이가 실제로 무엇인가

2026년 10월 기준 평가입니다. 공급자 기능은 바뀌므로, 중요한 줄은 의지하기 전에 직접
확인하시는 편이 좋습니다.

| | 오픈AI 클라우드 | 앤트로픽 클라우드 | 이 작업환경 |
|---|:---:|:---:|:---:|
| 내가 통제하는 하드웨어에서 실행 | X | X | O |
| 세션이 끝나도 맥락이 남는다 | △ | △ | O |
| 데스크톱·브라우저 제어 | △ | △ | O |
| 자격 증명과 권한 | X | △ | O |
| 작업 중에 UI 를 만들어 붙인다 | X | △ | O |
| **내가 자는 동안에도 돈다** | **O** | **O** | **X** |
| 데이터가 둔 자리에 남는다 | X | X | O |
| 비용을 예측할 수 있다 | △ | △ | O |

`O` 직접 지원 · `△` 부분적이거나 제약이 있음 · `X` 불가

굵은 줄은 클라우드가 가져갑니다. 집에 있는 기계의 전원이나 네트워크나 노트북 덮개가 멈춰도
호스팅 에이전트는 계속 돕니다. 켜 두는 호스트에 cron 과 재시작 정책을 걸면 격차가 줄기는
하지만 없어지지는 않습니다. 놓치면 안 되는 예약 작업은 클라우드의 몫입니다. 둘은 배타적인
선택이 아닙니다.

각 줄의 근거: [why-this-exists.md](why-this-exists.md)

## 무엇이 들어 있나

재시작해도 홈 디렉터리가 남는 데비안 컨테이너입니다.

- Node 22, Python 3.11, git, gh, ripgrep, jq
- Claude Code. 필요하면 opencode 와 Codex CLI 도 함께 설치합니다.
- [ValetFS](https://github.com/WinM2M/valet-fs). 비밀값을 컨테이너에 저장하지 않고
  명령 하나에만 건네줍니다. 설치할 때 공개된 SHA-256 을 확인합니다. 그 확인이 무엇을
  보장하고 무엇을 보장하지 않는지는 아래에 적었습니다.
- `workspace/` 는 호스트에서 바인드 마운트됩니다. 코드가 컨테이너 밖에 있으므로 컨테이너는
  버려도 되는 것으로 남습니다.

## 빠른 시작

도커가 필요합니다. 윈도우라면 WSL2 백엔드를 켠 Docker Desktop 입니다.

```sh
git clone https://github.com/YoungjuneKwon/self-hosted-ai-workspace
cd self-hosted-ai-workspace
./bootstrap.sh
```

스크립트는 필요한 도구를 확인한 뒤 도커 이미지와 홈 디렉터리용 이름 붙은 볼륨, 컨테이너를
만듭니다. 도커 밖에서는 실행한 디렉터리에 `workspace/` 만 만듭니다.

```sh
./bootstrap.sh --help         # 전체 옵션
./bootstrap.sh --no-valetfs   # 금고 없이
./bootstrap.sh --grant-vault  # 아래 허가 질문에 미리 답하고 시작
./bootstrap.sh --shell        # 이미 만든 작업환경에 셸로 들어가기
```

안에서 `claude` 를 한 번 돌려 로그인하면 세션이 볼륨에 남습니다.

## 부트스트랩이 묻는 것

컨테이너를 띄우기 전에, 에이전트가 매번 묻지 않고 `valetfs exec` 를 불러도 되는지
물어봅니다. 허가 범위도 함께 보여 줍니다. `exec`·`ls`·`status` 이고 `cat` 은 빠집니다.

정하지 않고 묻는 이유는, 에이전트에게 금고에 대한 상시 접근을 허용하는 것이 보안 결정이고
보안 결정은 운영자의 몫이기 때문입니다. 나중에 칠 명령을 안내하는 대신 답을 바로 적용하는
이유는, 운영자의 몫이어야 하는 것이 결정이지 타자가 아니기 때문입니다.

스크립트로 돌릴 때는 `--grant-vault` 나 `--no-grant-vault` 를 씁니다. 비대화형 실행은
기본으로 거절합니다. 나중에 답을 바꾸시려면 컨테이너 안에서 `valetfs setup-claude` 를
돌리거나 `~/.claude/settings.json` 을 고치면 됩니다.

비밀값이 에이전트에게 읽히지 않고 명령에 닿는 방법, 그리고 그것이 막아 주지 못하는 것은
[secrets.md](secrets.md) 에 적었습니다.

## 체크섬에 대해

설치기는 SHA-256 을 바이너리와 **같은 깃헙 릴리스**에서 받아 옵니다. 다운로드가 잘리거나
깨진 것은 잡지만 출처를 확립하지는 못합니다. 한쪽 파일을 바꿀 수 있는 쪽은 다른 쪽도 바꿀
수 있기 때문입니다.

ValetFS 릴리스는 cosign(keyless)으로 서명돼 있고 그쪽이 진짜 신뢰 경로입니다. 이미지를
가볍게 두려고 cosign 은 넣지 않았습니다. 더 강한 확인이 필요하시면 빌드 전에 직접
돌리시면 됩니다.

```sh
cosign verify-blob \
  --certificate SHA256SUMS.pem \
  --signature   SHA256SUMS.sig \
  --certificate-identity-regexp 'https://github.com/WinM2M/valet-fs/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com \
  SHA256SUMS
```

## 이것이 아닌 것

- **클라우드 대체재가 아닙니다.** 위의 굵은 줄을 보시면 됩니다.
- **GPU 장비가 아닙니다.** 호스팅 모델을 부르는 에이전트를 위한 작업환경이고, 로컬 추론은
  구성하지 않습니다.
- **환경 전부가 아닙니다.** 에이전트가 모는 브라우저, 터널, 호스트에 묶인 설정은 모두 범위
  밖입니다. 옮겨지지 않기 때문입니다.
- **독립적인 감사를 받지 않았습니다.** 제3자 보안 검토는 없었습니다. 돌리기 전에
  `docker/Dockerfile` 과 `bootstrap.sh` 를 읽어 보시는 편이 좋습니다.

ValetFS 는 이 저장소와 같은 저자가 공개한 것입니다.
