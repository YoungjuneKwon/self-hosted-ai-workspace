# 왜 만들었나

English: [../why-this-exists.md](../why-this-exists.md)

이 환경을 1년쯤 매일 썼다. 왜 그렇게까지 하냐는 질문을 여러 번 받아서, README 표의 각
줄에 대한 근거를 적는다.

## 내가 통제하는 하드웨어에서 실행

클라우드 작업환경이 몇 초 만에 뜨는 건 공급자 하드웨어에서 돌기 때문이다. 대신 무엇에
닿을 수 있는지도 공급자가 정하고, 나에게 묻지 않고 바꿀 수 있다. 내 기계에서는 그걸
내가 정한다.

## 세션이 끝나도 맥락이 남는다

호스팅 메모리는 무엇을 남길지 스스로 정하고, 남기는 것도 대개 요약이다. 나는 이전
세션의 메모와 결정을 거르지 않은 채로 에이전트가 읽기를 원했다.

이 항목은 몇 달 동안 잘못 봤다. 권한 쪽을 붙잡고 있는 동안 이건 있으면 좋은 것 정도로
뒀다. 실제로 매일 쓰다 보니 여기서 제일 크게 작용한 게 이쪽이었다. 저장소에서 시작하는
에이전트와, 저장소에 더해 우리 둘이 이미 합의해 둔 것까지 들고 시작하는 에이전트는 다른
도구다.

## 데스크톱·브라우저 제어

호스팅 에이전트는 브라우저와 데스크톱 접근을 제한한다. 내 기계에서는 그 권한을 내가
고르고, 잘못 고르면 그것도 내 책임이다.

## 자격 증명과 권한

뭐라도 만들게 만든 줄이 이거다.

내가 쓰던 환경에서는 자격 증명이 환경 변수나 `.env` 파일, 명령 출력으로 에이전트에게
닿았다. 에이전트가 한 번 읽으면 그 사본이 전사본에 남는다. 원본을 지워도 사본은 안
지워지고, 폐기할 수도 없다.

이걸 자격 증명 격리에 대한 문서를 쓰다가 배웠다. git remote URL 에 토큰을 남겨 뒀었고,
`git remote -v` 한 번에 전사본으로 복사됐다. 토큰은 교체했고 악용된 건 없다. 공개할
로그는 없고 내 진술이다.

그래서 [ValetFS](https://github.com/WinM2M/valet-fs) 를 만들었다. 키는 폰에 있고,
폰이 허용하는 동안 메모리로만 기계에 제공된다. `valetfs exec` 는 값을 자식 프로세스에
넘기므로, 에이전트는 명령을 쓰되 키는 보지 못한다.

```sh
valetfs exec fs:/keys/aws.env -- aws s3 ls s3://bucket
```

설치기는 공개된 SHA-256 을 확인하고 설치한다. 그 체크섬은 바이너리와 같은 릴리스에서
오기 때문에 다운로드가 깨진 건 잡아도 출처를 증명하지는 못한다. cosign 서명을 직접
확인하는 방법은 README 에 적었다.

부트스트랩은 에이전트에게 `valetfs exec` 무프롬프트 권한을 주기 전에 물어본다. 설정을
적용하는 건 스크립트가 해도 되지만, 권한을 줄지 말지는 사람이 정해야 한다.

ValetFS 는 내가 만들었다. 제3자 보안 감사는 받은 적이 없다.

## 작업 중에 UI 를 만들어 붙인다

에이전트가 화면을 고쳤으면 다음 수정 전에 그 결과를 띄워서 직접 보기를 바란다. 아니면
매 반복마다 내가 어디가 이상한지 말로 옮겨 줘야 한다.

## 내가 자는 동안에도 돈다

이건 클라우드가 낫다. 내 전기와 공유기와 노트북이 꺼져도 호스팅 에이전트는 돈다. 나는
켜 두는 기계에 cron 과 컨테이너 재시작 정책을 걸어 쓰고 대체로 버티는데, 「대체로」는
데이터센터가 말하는 가동률이 아니다.

놓치면 안 되는 예약 작업은 클라우드로 보낸다. 배타적인 선택이 아니고 나는 둘 다 쓴다.

## 데이터가 둔 자리에 남는다

개인에게는 들리는 것만큼 중요하지 않다. 계약이나 현지 법이 남의 자료를 어디서 처리할 수
있는지 제한할 때부터 중요해진다.

## 비용을 예측할 수 있다

기계를 갖고 있으면 작업환경 비용은 내가 가늠하기 쉬워진다. 다만 하드웨어는 고장 나고
전기도 공짜가 아니다. 모델 API 사용량은 어느 쪽이든 종량제고, 이 줄은 모델이 아니라
작업환경에 대한 것이다.

## 이게 맞지 않는 사람

AI 비서를 주에 몇 번 쓴다면 브라우저 탭을 쓰는 게 낫다. 이건 매일 쓰려고 만든 거고,
그게 아니면 세팅 비용이 안 맞는다.
