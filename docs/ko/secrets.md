# 비밀값, 그리고 왜 이 컨테이너에는 하나도 살지 않는가

English: [../secrets.md](../secrets.md)

## 보통 하는 방식의 문제

에이전트가 어떤 서비스를 쓰게 하려면 보통 **에이전트가 읽을 수 있는 자리에 키를
둡니다.** 환경 변수, `.env` 파일, git remote URL 에 박은 토큰.

그 키는 이제 컨테이너 안 모든 프로세스가 읽을 수 있고, 볼륨 백업마다 들어 있고,
어떤 로그나 전사본과도 명령 하나 거리에 있습니다. 그리고 에이전트는 읽습니다. 키를
쓰려고 읽는 순간 **그 키의 사본이 전사본 안에 생깁니다.** 내가 통제할 수도 폐기할 수도
없는 형태의 두 번째 사본입니다.

가정이 아닙니다. 살아 있는 자격 증명이 있어서는 안 될 자리로 흘러가는 **가장 흔한
경로**입니다.

## 이 작업환경이 대신 하는 것

[ValetFS](https://github.com/WinM2M/valet-fs) 는 키를 폰에 둡니다. 컨테이너의 데몬이
그것을 **메모리로만** 내어 주고 디스크에는 쓰지 않으며, 폰이 허용하는 동안만 유지합니다.
허가는 만료됩니다.

```sh
valetfs serve --join <연결 키>   # 이 기계를 폰과 연결한다
valetfs status                   # 무엇이 얼마 동안 제공되고 있는가
valetfs ls fs:/keys              # 이름만 본다. 값은 절대 보지 않는다
```

비밀값을 쓸 때는 **읽지 말고 필요한 명령에 넘깁니다.**

```sh
valetfs exec fs:/keys/aws.env -- aws s3 ls s3://bucket
valetfs exec --as API_KEY fs:/keys/openai.txt -- node script.mjs
valetfs exec --as-file KEYFILE fs:/keys/apple.p8 -- ./sign.sh
```

값은 자식 프로세스의 환경으로 들어갑니다. 셸 기록도, 에이전트의 컨텍스트도, 전사본도
거치지 않습니다.

`valetfs cat` 은 존재하고 비밀값을 그대로 출력합니다. **에이전트에서는 쓰지 마십시오.**
그것이 바로 여기서 막으려는 누출입니다.

## 손으로 하는 한 단계

```sh
valetfs setup-claude
```

Claude Code 는 에이전트가 자기 설정을 고치는 것을 막고, 기본적으로 자격 증명을 읽는
것도 막습니다. 둘 다 옳습니다. 에이전트가 제 뜻대로 금고를 열 수 있다면 디스크에 둔
키와 의미 있는 차이가 없습니다.

`setup-claude` 는 그 통로이고, **사람이 키보드 앞에서 한 번 실행하도록** 쓰였습니다.
`valetfs exec` · `valetfs ls` · `valetfs status` 에 대한 허가를 넣고, `valetfs cat` 은
일부러 넣지 않습니다. `--allow-cat` 을 붙여 그 의미를 받아들이지 않는 한은요.

```sh
valetfs setup-claude --print   # 넣을 JSON 만 보여주고 아무것도 쓰지 않는다
```

부트스트랩 스크립트는 이것을 대신 돌려 주지 않습니다. 그게 요점입니다.

## 그래도 내 몫으로 남는 것

- 허가가 열려 있는 동안에는 **탈취당한 컨테이너도 데몬에 비밀값을 요청할 수 있습니다.**
  통제 수단은 허가 창의 길이입니다. 짧게 유지하십시오.
- `valetfs exec` 는 값이 프로세스에 닿기까지를 지킵니다. 그 프로그램이 값을 로그에
  적는다면 그건 그 프로그램의 문제입니다.
- **화면 녹화와 스크린샷은 이 중 아무것도 지켜 주지 않습니다.** 공개 전에 가리십시오.

## ValetFS 를 안 쓴다면

`./bootstrap.sh --no-valetfs` 로 빼면 나머지는 그대로 돕니다. 그 길로 가신다면 최소한
**git remote 와 `workspace/` 안의 모든 파일에서는 키를 빼십시오.** `workspace/` 는
내 디스크에서 바인드 마운트되는 자리입니다.
